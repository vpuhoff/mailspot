# Результаты локальной проверки

Дата: 21 октября 2026. Linux x86_64, Intel Core i9-10900F, Go 1.26.8. Нативный бинарник, SQLite на локальном диске, WAL и `synchronous=FULL`.

Параметры: 8 параллельных SMTP-клиентов, новое подключение для каждого письма, оригинал приблизительно 4 KiB. Одновременно выполнялся HTTP-поиск `loadtest` каждые 500 мс. Для проверки удаления под нагрузкой срок хранения был уменьшен до 30 секунд, интервал очистки — до 2 секунд, предел — до 1 000 писем. До начала теста база была пустой.

| Показатель | Равномерный поток | Максимальный поток |
|---|---:|---:|
| Длительность | 120,011 с | 30,057 с |
| Подтверждённые письма | 1 200 | 7 340 |
| Фактическая скорость | 599,9/мин | 14 652,3/мин |
| Ошибки отправки | 0 | 0 |
| Средняя задержка SMTP | 9,38 мс | 32,71 мс |
| Максимальная задержка SMTP | 242,09 мс | 974,83 мс |
| Успешные запросы поиска | 239 | 59 |
| Ошибки поиска | 0 | 0 |
| Максимальный наблюдавшийся RSS сервера | 40,6 MiB | 55,3 MiB |

RSS снимался раз в 500 мс и не включает файловый кеш ОС или нагрузочный клиент. Сборка Docker-образа выполнялась параллельно части равномерного прогона. Показатели характеризуют эту машину и эти параметры, а не гарантированную производительность на другом оборудовании.

После равномерного потока оставалось 301 письмо, возраст самого старого — 30,17 с. Сразу после максимального потока оставалось 1 056 писем; спустя 3 секунды — ровно 1 000. Это ожидаемо для периодической очистки. `PRAGMA integrity_check` вернул `ok`; сервер завершился по SIGTERM с кодом 0.

Дополнительно прошли:

- `go test -race ./...`: интеграционные и модульные тесты без обнаруженных гонок.
- `go vet ./...`.
- `docker compose config --quiet`.
- Сборка Docker-образа и запуск от непривилегированного пользователя: контейнер `healthy`, `/healthz` возвращает `ok`. Тестовый контейнер остановлен.

**72-часовой прогон и поиск на базе в несколько миллионов писем не выполнялись.** Короткий тест подтверждает запас скорости на малой базе и работу очистки одновременно с приёмом; долговременную устойчивость на целевом объёме следует проверить отдельно. Команды для длительного прогона приведены в [README.md](README.md).
