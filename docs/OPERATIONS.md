# Эксплуатация

[← README](../README.md)

## Первый запуск и проверка

В каталоге проекта выполните:

```sh
cp .env.example .env
docker compose up -d --build
docker compose ps
curl --fail http://127.0.0.1:8080/healthz
```

Для отправки одного письма достаточно Python 3 со стандартной библиотекой:

```python
import smtplib
from email.message import EmailMessage

message = EmailMessage()
message["From"] = "sender@example.test"
message["To"] = "inbox@example.test"
message["Subject"] = "Проверка Mailspot"
message.set_content("Тестовое письмо с кириллицей.")

with smtplib.SMTP("127.0.0.1", 1025, timeout=10) as smtp:
    smtp.send_message(message)
```

Откройте веб-интерфейс и найдите письмо по слову `Проверка`. SMTP не требует AUTH и не предоставляет TLS.

## Изменение срока хранения

Например, для хранения неделю измените `.env`:

```dotenv
RETENTION=168h
CLEANUP_INTERVAL=1m
MAX_MESSAGES=7000000
```

Примените настройки:

```sh
docker compose up -d
```

При 600 письмах в минуту за неделю поступает 6 048 000 писем. Лимит количества и срок действуют одновременно: старые письма могут удаляться раньше срока при превышении `MAX_MESSAGES`. Уменьшение срока применяется при следующем запуске очистки, включая первый проход после перезапуска.

Для локального бинарника задавайте переменные окружения непосредственно перед запуском. Полный список настроек находится в [README](../README.md#настройки).

## Диск, данные и остановка

Compose хранит базу в постоянном томе `mailspot-data`; локальный бинарник — в `data/mailspot.db`, если `DB_PATH` не изменён. Рядом с файлом БД во время работы могут находиться файлы `-wal` и `-shm`.

Не удаляйте файлы SQLite работающего сервера. Для файлового резервного копирования остановите все процессы, использующие эту базу, скопируйте весь каталог данных и затем запустите сервер. Обычное копирование только `.db` во время записи не является согласованной резервной копией.

```sh
# Остановить контейнер, сохранив данные
docker compose stop

# Запустить снова
docker compose start
```

Для восстановления используйте отдельный пустой каталог или том и сохраните права доступа. Контейнер работает с UID/GID `10001:10001`. Первый проход очистки после запуска применит текущие настройки хранения и к восстановленным письмам.

Размер `.db` не обязан сразу уменьшаться после очистки: свободные страницы переиспользуются, а освобождение места на диске выполняется постепенно. Контролируйте свободное место с учётом оригиналов, индексируемого текста и поискового индекса. При заполнении диска новые письма не должны считаться доставленными: отправитель получит временную SMTP-ошибку и должен повторить доставку позже.

## Диагностика

```sh
docker compose ps
docker compose logs --tail=100 mailspot
curl --fail http://127.0.0.1:8080/healthz
```

| Симптом | Что проверить |
|---|---|
| Нет соединения с SMTP | Адрес, порт, состояние процесса. Из другого контейнера `localhost` указывает на сам этот контейнер; используйте `mailspot:1025` в общей сети. |
| SMTP `421` | Достигнут `MAX_CONNECTIONS`. Ограничьте параллелизм клиента и повторите доставку позже. |
| SMTP `451` | Логи сервера, свободное место, права каталога данных, ошибки SQLite. |
| SMTP `552` | Оригинал превышает `MAX_MESSAGE_BYTES`. Проверьте размер вместе с MIME-кодированием вложений. |
| Письмо не находится | Запрос должен содержать минимум 3 символа. Проверьте срок хранения, предел количества и `truncated`; вложения не индексируются. |
| API вернул `404` для ранее видимого письма | Оно могло быть удалено автоочисткой. |
| Ошибка `permission denied` для БД | Права каталога и файлов, особенно при замене Docker-тома bind mount. |

## Проверка длительной нагрузки

```sh
go build -mod=vendor -buildvcs=false -o bin/loadtest ./cmd/loadtest
./bin/loadtest -duration 72h -rate 600 -workers 8 -size 4096
```

Выполняйте команду при работающем Mailspot. Нагрузочный клиент также отправляет HTTP-поисковые запросы. Он создаёт реальные письма и завершает работу с ненулевым кодом при ошибках. Подберите `-size` под ваши письма и контролируйте память процесса и свободное место на диске.

Измеренные результаты и ограничения короткого прогона приведены в [BENCHMARK.md](../BENCHMARK.md).
