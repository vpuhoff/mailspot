# HTTP API

[← README](../README.md)

Базовый адрес при стандартном запуске: `http://127.0.0.1:8080`. Авторизации нет. Все перечисленные методы используют `GET`; API предназначен для чтения. Приём писем осуществляется через SMTP.

## Список и поиск

`GET /api/messages`

| Параметр | Поведение |
|---|---|
| `q` | Подстрока для поиска по отправителю, получателям, теме и индексируемому тексту. Пробелы по краям удаляются. Пустой запрос возвращает последние письма; непустой должен содержать от 3 до 200 символов и не содержать нулевой байт. |
| `before` | Возвращает письма с ID меньше указанного положительного числа. Без параметра — первая страница. |
| `limit` | От 1 до 100. По умолчанию, при неверном значении или выходе за диапазон — 50. |

Пример запроса:

```sh
curl --get \
  --data-urlencode 'q=example.test' \
  --data-urlencode 'limit=50' \
  http://127.0.0.1:8080/api/messages
```

Пример структуры ответа:

```json
{
  "messages": [
    {
      "id": 123,
      "sender": "sender@example.test",
      "recipients": "alice@example.test, bob@example.test",
      "subject": "Тестовое письмо",
      "received_at": 1792533600000,
      "size": 512,
      "truncated": false
    }
  ],
  "next_before": 123
}
```

Письма отсортированы по убыванию ID. Для следующей страницы передайте `before=123`, сохранив `q` и `limit`. Непустая страница всегда содержит `next_before`, даже если следующих писем нет. Завершайте обход при пустом `messages`; в таком ответе `next_before` равен 0. Не отправляйте курсор 0 для продолжения обхода: он снова вернёт первую страницу.

Поиск не учитывает регистр; операторы поискового языка не поддерживаются. Индекс содержит только сохранённый декодированный текст в пределах `MAX_BODY_BYTES`. Вложения не индексируются.

## Письмо

`GET /api/messages/{id}`

Возвращает один объект с теми же полями, что и в списке, и полем `body` с декодированным текстом. Если текст пустой, поле `body` отсутствует. Оригинал и вложения в JSON не включаются.

| Поле | Значение |
|---|---|
| `id` | Числовой идентификатор письма |
| `sender` | Отправитель из SMTP-конверта, может быть пустым |
| `recipients` | Получатели SMTP-конверта, объединённые через запятую |
| `subject` | Декодированная тема или `Без темы` |
| `received_at` | Время приёма в миллисекундах Unix, UTC |
| `size` | Размер сохранённого оригинала в байтах |
| `truncated` | Текст сокращён либо MIME разобран не полностью |
| `body` | Декодированные текстовые части, включая HTML как текст |

## Оригинал

`GET /messages/{id}/raw`

Возвращает исходное письмо с MIME-частями и вложениями. Тип ответа — `application/octet-stream`, имя скачиваемого файла — `message-{id}.eml`.

```sh
curl --fail http://127.0.0.1:8080/messages/123/raw -o message-123.eml
```

## Доступность и ошибки

`GET /healthz` возвращает `200` и текст `ok`, если проверка соединения с БД прошла, иначе `503`. Эта проверка не подтверждает возможность записи на диск или доступность SMTP.

Успешные ответы API используют `application/json; charset=utf-8`. Ошибки возвращаются обычным текстом, а не JSON.

| Статус | Причина |
|---|---|
| `400` | Недопустимая длина поискового запроса или нулевой байт в нём |
| `404` | Письмо отсутствует, уже удалено очисткой либо указан неверный ID; также неизвестный маршрут |
| `405` | HTTP-метод не поддерживается для маршрута |
| `503` | Ошибка хранилища, таймаут операции или исчерпание HTTP-соединений |

Письмо может быть удалено автоочисткой между получением списка и запросом деталей. Клиенту следует обрабатывать такой `404` как обычную ситуацию.
